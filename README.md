# MUI DynamicTable

Reusable JavaScript/JSX table library for Next.js client components, powered by MUI and TanStack Table.

## Install and build

```sh
npm install
npm run check
```

## Next.js demo

```sh
cd examples/nextjs-demo
npm install
npm run dev
```

The demo is local-file linked to the package. Build the library first. Visit `/` for client mode. `app/spring-page.jsx` is an integration example, not a Next.js route; copy it into `app/spring/page.jsx` when a Spring API is available.

## API

`<DynamicTable columns={columns} data={rows} />` for client mode.

`<DynamicTable columns={columns} dataSource={fetchPage} />` for server mode, where `fetchPage({pagination,sorting,columnFilters,globalFilter,signal})` returns `{rows,rowCount}`. Keep `dataSource` referentially stable with `useMemo`/`useCallback` to avoid repeat requests.

Optional props: `title`, `getRowId`, `enableSorting`, `enableFiltering`, `enablePagination`, `enableRowSelection`, `enableGlobalSearch`, `enableColumnFilters`, `pageSize`, `pageSizeOptions`, `rowActions`, `toolbarActions`, `exportHandlers`, `onRowSelectionChange`, `onStateChange`, `loading`, `error`, `emptyMessage`, `initialSorting`, `sx`.

Columns use TanStack Table v8 definitions (`accessorKey`, `header`, `cell`, `enableSorting`, `enableColumnFilter`). Shift-click sorts by multiple columns. Supply `getRowId` for durable selection across server pages.

`exportHandlers` is an object with `csv`, `excel`, `pdf` callback functions. They receive `{rows,columns,state}`. Current `rows` are the visible page; implement server exports to export all matching records. `exportRowsAsCsv` supports basic flat accessorKey columns. PDF/XLSX must be generated by the application backend or a separate export library.

## Spring Boot API contract

`GET /api/customers?page=0&size=20&sort=name,asc&search=abc&filter.status=Active`

Spring should return `Page<Customer>` JSON with `content`, `totalElements`, and `totalPages`. The backend must implement `search` and `filter.*` parameters, validate sort/filter column names, authorize data access, and cap page size. Spring's built-in pageable resolver handles `page`, `size`, `sort`, but **does not automatically implement search/filter**.

Use `createSpringDataSource({url:'/api/customers'})`. Configure Next.js rewrite/proxy or a same-origin API route to forward requests to Spring Boot. For secure full exports, implement `POST /api/customers/export/xlsx` and `/pdf` with filtering/sorting criteria in request JSON; use `exportWithEndpoint` for download. CSRF/auth and content-disposition requirements depend on your deployment.

## Publishing

1. Replace `@company` with your real npm scope in `package.json`, `.github/workflows/publish.yml`, and demo files.
2. Configure GitHub Actions variable `ARTIFACTORY_NPM_URL`, e.g. `https://example.jfrog.io/artifactory/api/npm/npm-local/`.
3. Configure secret `ARTIFACTORY_NPM_TOKEN` with a token scoped to publishing to that repository.
4. Protect the `release` environment and require approval. Prefer short-lived JFrog OIDC tokens when configured.
5. Commit `package-lock.json` after `npm install` and change workflow install steps to `npm ci` for reproducible builds, merge through CI, bump `package.json` version, and push matching tag (e.g. `v0.1.0`).
6. Consumers configure their scope registry and authenticate via approved CI secret management.

The package uses React/MUI/TanStack as peer dependencies, so consuming apps provide compatible versions. Export code is optional and does not ship a PDF/XLSX implementation.

## Notes

The default table performs client filtering and pagination for `data`; server mode delegates all filtering/sorting/pagination to the API. Server row selection is page-local unless your app persists selected row IDs. This is a starter library; add accessibility, cross-browser, and large-dataset performance tests before enterprise rollout.
